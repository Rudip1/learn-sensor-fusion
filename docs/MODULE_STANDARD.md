# Learning-module standard

Every `learn-*` repository in [robotics-learning](https://github.com/Rudip1/robotics-learning) follows this
standard. It is the specification a module is built against; `docs/CHAPTER_PLAN.md` in each module says *what* to
teach, this file says *how*.

## What a module is

A self-contained course on one robotics subject, written so that a reader can learn the subject from it alone:
**theory → C++ implementation → notebook where the reader runs, checks and breaks it.** The C++ library is the
substance; Python is the thin layer that makes it interactive.

## Layout

```
learn-<topic>/
├── README.md            what the module teaches, chapter table, one figure, quick start
├── HOW_TO_RUN.md        build, test, notebooks (local and Colab)
├── LICENSE              Apache-2.0 (code);  1_theory/ is CC BY 4.0 (say so in README)
├── CMakeLists.txt       top-level C++ build
├── pyproject.toml       scikit-build-core + pybind11 -> `pip install -e .` builds the C++ and the Python module
├── Makefile             make build | test | notebooks | all
├── 1_theory/            NN_<chapter>.md, one per chapter; figures/ (generated by tools/, never hand-edited PNGs)
├── 2_notebooks/
│   ├── exercises/       NN_<chapter>.ipynb   (the reader's copy: ✏️ cells left to do)
│   └── solutions/       NN_<chapter>.ipynb   (same notebook, solved, executes top to bottom)
├── cpp/
│   ├── include/<pkg>/   public headers
│   ├── src/
│   ├── tests/           Catch2 v3 via FetchContent; every algorithm checked against a reference
│   └── examples/        small command-line programs, one per chapter where it makes sense
├── python/<pkg>/        pybind11 bindings + small helpers (plotting, data loading); no algorithms here
├── data/                small files only (< 5 MB total); anything larger is fetched by tools/get_data.sh
├── tools/               figure scripts, data download, notebook strip/execute
└── .github/workflows/ci.yml   build + C++ tests + execute every solution notebook
```

`<pkg>` is a short snake_case name (`motion_planning`, `state_estimation`, …), the same for the C++ namespace, the
include directory and the Python module.

## A chapter

Each chapter in `docs/CHAPTER_PLAN.md` produces four things with the same number `NN`:

1. **`1_theory/NN_<chapter>.md`** — the idea, the model, the derivation in full (GitHub-rendered LaTeX `$$…$$`),
   the algorithm as numbered steps, common mistakes, references (textbooks and original papers). Written to teach,
   not to report: no "in this lab we…".
2. **C++ in `cpp/`** — the algorithm, clean and general (templates or Eigen types, no globals, no hard-coded
   scenario). Doxygen comments that cite the theory equation they implement (`// eq. (3.4) in 1_theory/03_…`).
3. **Tests in `cpp/tests/`** — against something independent: a closed form, a hand-worked example from the theory
   file, or an established library (OMPL, OpenCV, Pinocchio, GTSAM, Open3D, …) used *only* in tests or notebooks
   as a reference, never as the implementation.
4. **Notebook `2_notebooks/{exercises,solutions}/NN_<chapter>.ipynb`**, in this order:
   - short recap (5–10 lines) linking to the theory file;
   - runnable cells that call the C++ through the Python module and plot the result;
   - ✏️ **exercises**: the reader implements or derives something small; an `assert` cell checks it;
   - 🔨 **break it** cells: change one assumption (noise, singularity, bad initial guess, wrong frame) and see the
     failure the theory predicts;
   - a closing "what to remember" list of 3–5 lines.
   First cell installs the module so it runs in Colab:
   `%pip install -q git+https://github.com/Rudip1/learn-<topic>`.

## Languages

- **C++17**, CMake ≥ 3.20, Eigen 3.4; other dependencies only through FetchContent or as optional.
- **Python** ≥ 3.10: bindings, plotting (matplotlib), data loading, notebook glue. If something is an algorithm,
  it belongs in C++.
- MATLAB code from the original material is not kept; port the ideas to C++.
- ROS 2 integration is not part of a module. Link to the project repositories that use the module instead
  (`README.md` → "Used in").

## Content rules

- **No institution branding**: no university, course or lab names, course codes, lab numbers, student IDs,
  grades, or instructor names in files, file names or commit messages. The module is a subject, not a course.
- **Only own work is published.** Course-provided frameworks, handouts, template code, datasets with
  restrictive licences and instructor solutions are removed and re-written from scratch. Own reports may be
  mined for theory text and figures.
- **Collaborators are credited**: where a chapter grows out of joint work, add an "Acknowledgements" line in the
  README naming the person (no e-mail addresses).
- **No generated junk in git**: `__pycache__`, `.pyc`, build directories, `.asv`, `desktop.ini`, notebook outputs
  in `exercises/`, zips of code. `.gitignore` covers them.
- **Every number printed in the theory or README is produced by code in the repository.** If it cannot be
  reproduced, it is not printed.
- Unknowns are written as `TODO:` in the text, never invented.

## Style

- Plain, exact English. Define each symbol once, keep one notation through the module (put the table in
  `1_theory/00_notation.md`).
- Standard names from the textbooks (Thrun–Burgard–Fox, Siciliano et al., Hartley–Zisserman, LaValle, Lynch–Park)
  and cite them.
- C++ style: `snake_case` functions and variables, `PascalCase` types, `.hpp/.cpp`, `clang-format` (Google base,
  4-space indent, 110 columns).

## Done means

- `pip install -e .` and `make test` pass on a clean Ubuntu 24.04; CI is green.
- Every solution notebook executes top to bottom in CI.
- README has: one-line summary, a figure or GIF, chapter table (theory · code · notebook links), quick start,
  "Used in" links, licence note.
- `ROADMAP.md` lists any chapter from the plan that is not finished yet. Finish chapters in order; a finished
  chapter beats three half-done ones.

## Commits

Small commits with plain messages that describe the change. Work on a branch and open a pull request.
